# FileFlow

เว็บแปลงไฟล์ภาษาไทย ใช้งานในเบราว์เซอร์ ไฟล์ทั้งหมดถูกประมวลผลบนอุปกรณ์ของผู้ใช้ ไม่มี API รับไฟล์ ไม่มีระบบเก็บไฟล์หรือประวัติการใช้งาน

## เริ่มใช้งาน

ต้องมี Node.js 24 ขึ้นไป

```bash
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดงใน terminal จากนั้นเลือกไฟล์ เลือกรูปแบบปลายทางข้างไฟล์ แล้วกด **แปลงไฟล์** ดาวน์โหลดทีละไฟล์หรือรวมเป็น ZIP ได้

```bash
npm test
npm run build
npm run preview
```

`dist/` เป็นเว็บแบบ static สำหรับนำขึ้นโฮสต์ได้ ไม่ต้องมี backend หรือ API key โดยโหลดไลบรารีแปลงไฟล์แยกตามชนิดงาน

## รองรับการแปลง

| ต้นทาง | ปลายทาง |
| --- | --- |
| JPG / JPEG | PNG, WebP, PDF |
| PNG | JPG, WebP, PDF |
| WebP | PNG, JPG, PDF |
| GIF / BMP | PNG, JPG, WebP, PDF |
| PDF | PNG, JPG, TXT |
| DOCX | TXT, HTML |
| TXT (UTF-8) | PDF |
| CSV | XLSX, JSON, TSV |
| TSV | XLSX, JSON, CSV |
| XLSX | CSV, JSON, TSV |
| JSON | CSV, XLSX, TSV |

## ขอบเขตและข้อจำกัด

- สูงสุด 20 ไฟล์ต่อคิว, 25 MB ต่อไฟล์, รวมไฟล์ต้นทาง 100 MB
- PDF สูงสุด 60 หน้า ภาพแต่ละหน้า/ไฟล์ไม่เกิน 20 ล้านพิกเซล ผลลัพธ์รวม ZIP ไม่เกิน 100 MB
- PDF หลายหน้าเป็นภาพแยกตามหน้าใน ZIP ข้อความ PDF ต้องมี text layer อยู่แล้ว ยังไม่มี OCR หรือการปลดล็อกรหัสผ่าน
- DOCX → HTML ใช้โครงสร้างหัวข้อ ตาราง รูปภาพเท่าที่อ่านได้ ไม่รับประกันเค้าโครงหน้าเหมือน Word ต้นฉบับ ยังไม่มี DOCX → PDF แบบรักษาเค้าโครง
- TXT → PDF เป็นภาพของหน้าขนาด A4 รองรับภาษาไทยจากฟอนต์อุปกรณ์ แต่เลือกหรือค้นหาข้อความในผลลัพธ์ไม่ได้ ข้อความสูงสุด 200,000 ตัวอักษร/60 หน้า
- GIF ใช้ภาพนิ่งเฟรมแรก JPG/PDF ใช้พื้นหลังสีขาวแทนส่วนโปร่งใส ภาพเป็น PDF จัดพอดีหน้าขนาด A4
- XLSX ใช้ค่าข้อมูลและผลสูตรที่บันทึกไว้ ไม่คำนวณสูตร ไม่รักษาสไตล์ต้นฉบับ สูงสุด 100,000 แถว และ 1,000 คอลัมน์
- XLSX หลายชีต → CSV/TSV เป็น ZIP แยกชีต ส่วน JSON หลายชีตเป็น `{ "sheets": [{ "name": "Sheet 1", "rows": [["หัวคอลัมน์"], ["ค่า"]] }] }`
- JSON ชีตเดียวส่งออกเป็นอาร์เรย์ของแถวรวมแถวหัวตาราง การนำเข้ารับทั้งอาร์เรย์ของอาร์เรย์ และอาร์เรย์ของออบเจ็กต์ (รวมคีย์ของทุกแถวเป็นหัวตาราง)
- CSV/TSV ส่งออกเป็น UTF-8 พร้อม BOM และ escape ข้อความที่อาจถูกตีความเป็นสูตรเมื่อเปิดในโปรแกรมตารางข้อมูล
- ไม่รองรับ .doc, .xls, HEIC, วิดีโอ, ไฟล์ Office/PDF ที่มีรหัสผ่าน
- เอกสาร Office ตรวจขนาดข้อมูลภายใน ZIP ไม่เกิน 100 MB และ 2,000 entries ก่อนอ่านด้วยไลบรารี ไฟล์ใกล้ขีดจำกัดอาจใช้เวลาและหน่วยความจำมาก
- แนะนำ Chrome หรือ Edge รุ่นปัจจุบัน ต้องมี Canvas, Web Workers และ Intl.Segmenter
- ปิดหรือรีเฟรชหน้าเว็บแล้วคิวจะหายไป ดาวน์โหลดผลลัพธ์ก่อนออกจากหน้า

## Deploy บน GitHub Pages

1. อัปโหลด source code ไปที่ repository ของคุณ
2. ใน Settings → Pages เลือก Source เป็น GitHub Actions (ความพร้อมใช้งานสำหรับ private repository ขึ้นอยู่กับแผน GitHub)
3. เปิด Actions → **Deploy to GitHub Pages (manual)** → Run workflow

Workflow **Build and test** ตรวจการแปลงไฟล์และ build ทุก push ไป `main` และทุก pull request ส่วนการ deploy ต้องสั่งแยกเอง `base: './'` รองรับการอยู่ใต้ path ของ repository

## โครงสร้าง

```text
src/main.jsx        หน้าจอ คิวแปลงไฟล์ และดาวน์โหลด
src/model.mjs       รูปแบบไฟล์และการตรวจขนาด
src/converters.mjs  แปลงภาพ PDF เอกสาร และตาราง
src/style.css       responsive UI
tests/              ทดสอบข้อมูลภาษาไทย หลายชีต และการแปลงจริง
.github/workflows/  CI และ deploy แบบ manual
```

ไลบรารีหลัก: React, Vite, PDF.js, pdf-lib, Mammoth, DOMPurify, ExcelJS, Papa Parse และ fflate แต่ละไลบรารีใช้สิทธิ์ตามใบอนุญาตของเจ้าของ

ฟอนต์โหลดจาก Google Fonts; การร้องขอฟอนต์ไม่มีข้อมูลไฟล์ที่เลือก ไม่มี analytics หรือบริการแปลงไฟล์ภายนอก
